Factory Inventory Management System

システムアーキテクチャ

System Architecture

工場の在庫・受注・需要予測・支出分析を扱うデモアプリケーション。 Vue 3 のシングルページアプリが FastAPI を呼び、サーバーは JSON ファイルを メモリに読み込んで応答する。データベースも認証機構も持たない。

A demo application for factory inventory, orders, demand forecasting and spending analysis. A Vue 3 single-page app calls FastAPI, which serves data it loaded from JSON files into memory. There is no database and no authentication.

Vue 3.4 + Vite 5 FastAPI + Pydantic v2 JSON / in-memory frontend 8,511 行 frontend 8,511 lines backend 482 行 backend 482 lines

構成図

Architecture

データフロー — フィルタ操作を起点に

Data Flow — Starting From a Filter Change

このアプリの中心的な仕組みは、画面上部にある 4 つのフィルタ （Time Period / Location / Category / Order Status）が全画面のデータに効くこと。 1 回の操作が下の順で伝わる。

The central mechanism of this app is that the four filters at the top of the screen (Time Period / Location / Category / Order Status) apply to the data on every screen. A single change propagates in the order below.

1

ユーザーが FilterBar の select を変更

The user changes a select in FilterBar

client/src/components/FilterBar.vue — 全ルートで共通表示される （App.vue が <router-view> の外に置いている）
client/src/components/FilterBar.vue — shown on every route, because App.vue renders it outside <router-view>
2

シングルトン composable の ref が更新される

A ref inside a singleton composable updates

useFilters.js は ref を モジュールスコープで定義している。 つまり import した全コンポーネントが同一インスタンスを共有する — これが Pinia を使わずに全画面同期している理由
useFilters.js declares its refs at module scope, so every component that imports it shares the same instance. This is why all screens stay in sync without Pinia.
3

watch が発火し、各ビューが再取得

A watch fires and each view refetches

getCurrentFilters() が { warehouse, category, status, month } を返す。 selectedPeriod のみ month にキー名が変わる
getCurrentFilters() returns { warehouse, category, status, month }. Note that selectedPeriod is the one field renamed, to month
4

api.js が query string にしてリクエスト

api.js turns them into a query string

URLSearchParams で組み立て、axios で http://localhost:8001/api/... を叩く。単一の API クライアント 106 行
Built with URLSearchParams, sent by axios to http://localhost:8001/api/.... One API client, 106 lines
5

FastAPI がメモリ上のリストを絞り込む

FastAPI narrows the in-memory lists

apply_filters() が warehouse / category / status を、 filter_by_month() が月と四半期を処理。 いずれも Python のリスト内包表記で、SQL は介在しない
apply_filters() handles warehouse / category / status and filter_by_month() handles months and quarters. Both are plain list comprehensions — no SQL is involved
6

Pydantic が response_model で検証して返す

Pydantic validates against response_model

モデルに無いフィールドは応答から除去される。 JSON の構造を変えたらモデルも直す必要がある
Fields absent from the model are stripped from the response. Change the JSON structure and you must update the model too
7

生データは ref、派生データは computed

Raw data in ref, derived data in computed

allOrders / inventoryItems に生データを入れ、 KPI や集計は computed で算出する。 この規約がコードベース全体で一貫している
Raw responses go into allOrders / inventoryItems; KPIs and aggregates are derived in computed. This convention holds consistently across the codebase

読む前に知っておくべき癖

Quirks Worth Knowing Before You Read the Code

フロントが呼ぶのにバックエンドに無い API が 3 つある

Three APIs the frontend calls do not exist on the backend

ブラウザのコンソールに 404 が出続ける。 PurchaseOrderModal.vue も Dashboard.vue:289 から参照されているが ファイル自体が存在せず、[Vue warn] Failed to resolve component になる。 意図的に空けられた演習用の穴。

The browser console shows continuous 404s. PurchaseOrderModal.vue is referenced from Dashboard.vue:289 but the file does not exist, producing [Vue warn] Failed to resolve component. These are gaps left open on purpose as exercises.

在庫データに月フィルタは効かない

The month filter does not affect inventory

filter_by_month() は item['order_date'] を見るが、 在庫アイテムは order_date を持たない。 時間軸が無いので、月を選んでも在庫は絞り込まれない。

filter_by_month() looks at item['order_date'], but inventory items have no order_date. With no time dimension, choosing a month does not narrow inventory at all.

QUARTER_MAP が 2025 年決め打ち

QUARTER_MAP is hard-coded to 2025

Q1-2025 〜 Q4-2025 のみ定義。 他の年を渡すとエラーにならず静かに全件返す。

Only Q1-2025 through Q4-2025 are defined. Pass any other year and it does not error — it silently returns everything.

書き込みは永続化されない

Writes are never persisted

データは module レベルのグローバル変数。プロセスが生きている間は保持されるが、 サーバーを再起動すると JSON から読み直され、変更は消える。

The data lives in module-level globals. It survives while the process runs, but restarting the server reloads the JSON and discards every change.

フロント偏重の行数比

The code is heavily frontend-weighted

frontend 8,511 行 / backend 482 行。約 18 : 1。 ロジックの大半が Vue 側にある。

8,511 lines of frontend against 482 of backend — roughly 18 : 1. Most of the logic sits on the Vue side.

本番参考にはしない

Not a reference for production

認証なし・CORS 全許可（allow_origins=["*"]）・入力検証は Pydantic の型チェックのみ。デモ専用の構成。

No authentication, fully open CORS (allow_origins=["*"]), and input validation limited to Pydantic type checks. This shape is for the demo only.
